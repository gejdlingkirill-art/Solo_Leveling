# Система охотника — Solo Leveling (Update 4.7)

Статическое PWA-приложение на HTML, CSS и JavaScript. Не требует сборки, Node.js или платного хостинга.

## Что внутри

- `index.html` — приложение целиком.
- `assets/` — изображения теней, боссов и экипировки.
- `manifest.json` — настройки PWA.
- `sw.js` — Service Worker и офлайн-кэш.
- `icon.svg` — иконка приложения.

## Публикация через GitHub Pages (бесплатно для публичного репозитория)

1. Создайте новый **Public** репозиторий на GitHub, например `solo-leveling-hunter`.
2. Загрузите в корень репозитория **все файлы и папку `assets` из этого проекта**. Не загружайте ZIP вместо распакованных файлов.
3. Откройте `Settings` → `Pages`.
4. В разделе `Build and deployment` выберите `Deploy from a branch`.
5. В качестве ветки выберите `main`, папку `/ (root)`, затем нажмите `Save`.
6. Подождите, пока GitHub Pages опубликует сайт. Адрес обычно имеет вид `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

Если GitHub предлагает загрузку файлов через браузер на iPhone: в репозитории нажмите `Add file` → `Upload files`, затем выберите распакованные файлы. Убедитесь, что `index.html` лежит непосредственно в корне репозитория, а не внутри вложенной папки.

## Важно о сохранениях

Прогресс хранится в локальном хранилище браузера на устройстве. Перед сменой хостинга откройте старый сайт и экспортируйте JSON-резервную копию из приложения. После открытия нового адреса импортируйте JSON, если приложение не перенесло данные автоматически. Данные разных доменов браузер хранит отдельно.

## Обновление проекта

Чтобы выпустить обновление, замените файлы в репозитории новыми файлами проекта, сохранив `assets/` и структуру корня. После коммита GitHub Pages опубликует изменения автоматически. Если приложение показывает старую версию, закройте установленную PWA и откройте сайт в Safari; Service Worker может некоторое время держать кэш.

## Проверка структуры

В корне репозитория должны находиться:

```text
index.html
sw.js
manifest.json
icon.svg
assets/
README.md
.nojekyll
```

Приложение является статическим сайтом; серверная база данных не требуется. Не добавляйте в репозиторий экспортированные JSON-сохранения, если не хотите публиковать личный прогресс.
